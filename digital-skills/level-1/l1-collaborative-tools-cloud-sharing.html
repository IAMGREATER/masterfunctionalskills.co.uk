Cloud Sharing, Permissions and Collaboration

Three Non-Negotiable Exam Golden Rules

Golden Rule 1: Apply Least-Privilege Permissions (View vs Comment vs Edit)

Never grant full 'Can Edit' permissions if recipients only need to read ('Can View') or leave feedback notes ('Can Comment' / Suggesting mode).

✗ Choosing 'Anyone with the link can EDIT' for a confidential master timetable
✓ Specific Named People > 'Can Comment' + 7-day link expiry
Golden Rule 2: Use @Mentions Inside Comments & Track Versions During Co-Authoring

Cloud co-authoring shows coloured live cursors so two colleagues edit different sections safely without creating conflicting file copies (`Draft_v1_John.docx`, `Draft_v2_Sarah.docx`).

✗ Emailing 6 sequential attachment copies back and forth over 3 days
✓ Share one live cloud link > `@mention` reviewer inside margin Comment thread
Golden Rule 3: Set Link Expiration Dates & Revoke Access Once Task Completes

Expiring temporary contractor links prevent forgotten access vulnerabilities months later.

✗ Leaving permanent unrestricted sharing links open across finished projects
✓ Set 7-day / 30-day expiry and revoke link when sign-off completes

Step-by-Step Teaching & Key Concepts

1
Sharing Links & Setting Access Permissions

Instead of emailing large document attachments back and forth (which results in five conflicting versions), share a single live cloud document:

  1. Click the blue Share button in the top right corner.
  2. Choose access permissions:
    • Can Edit: The recipient can type, format, delete, and add content. Use for active co-workers.
    • Can View (View Only): The recipient can read and download the file, but cannot make any edits. Ideal for final drafts or external clients.
  3. Enter their specific email address and click Send.
Cloud Share Permissions Dialogue
Share 'Annual_Audit_2026.docx'
2
Real-Time Co-Authoring

When multiple people open the same cloud document, you can see their initials or avatar in the top ribbon:

  • A coloured cursor shows where your colleague is currently typing.
  • Changes save automatically in real time without conflicting copies.
3
Using Comments and Resolving Feedback

To give feedback without changing the author's words:

  1. Highlight the sentence and click New Comment (Ctrl + Alt + M).
  2. Type your question or suggestion (e.g. '@Sarah please verify these medication numbers').
  3. Once the feedback is addressed, click Resolve. The comment thread is tucked away neatly without cluttering the page.

Worked Model 1 • Core StandardStep-by-Step Accredited Guide
Exam Scenario Prompt: A training coordinator writes an exam timetable and wants a colleague to proofread it. The coordinator wants the colleague to read the timetable and suggest notes without having permission to accidentally delete or change any exam dates. Explain how the coordinator should configure the sharing permissions.
Step 1: Set sharing permission [B1]
Set the link permission to 'Can View' (or 'View Only' / 'Review Only').
Tutor Marking Rationale: Prevents unauthorized or accidental direct modification of document text.
Step 2: Explain feedback mechanism [B1]
Allow the colleague to use the 'Comments' tool to suggest revisions.
Tutor Marking Rationale: Enables constructive feedback while preserving source document integrity.
Tutor Abdul's Exam Golden Rule: In Level 1 exams, always distinguish between 'Can Edit' and 'Can View (View Only)'. View Only is the answer whenever accidental changes must be prevented.
Worked Model 2 • Applied Workplace Scenario Exam Scenario Model 2 • Fixing Conflicting Feedback via Live Comments & Resolve
Exam Scenario Prompt 2: Three tutors are reviewing a shared Google Docs / Word Online assessment schedule. One tutor writes feedback directly inside red text over the timetable itself, confusing everyone. Explain the proper collaborative workflow.
Step 1: Switch to Reviewing / Suggesting Mode & Insert Comments [B1][M1]
Highlight the target row > click 'New Comment' (or switch to Reviewing/Suggesting mode) and use `@ManagerName` to assign action cleanly in the side margin rather than altering official body text directly.
Tutor Marking Rationale: Preserves clean document layout and tracks author responsibility automatically.
Step 2: Track Approvals Cleanly via Resolve Button [B1]
Once the coordinator updates the time, click 'Resolve' on the margin comment thread so open vs completed feedback remains crystal clear.
Tutor Marking Rationale: Demonstrates structured modern cloud co-authoring mastery.
Tutor Abdul's Distinction Tip: Spot 'Anyone with the link' in Share menus carefully: if forwarded onward by a careless colleague, literally anyone on the Internet can open it! Always choose **Specific people / Organisation only** for workplace files.

Critical Examiner Traps & Common Pitfalls

Trap 1: Emailing Static Attachments Instead of Collaborating on One Cloud Copy
Leads to two people editing different offline copies so somebody's afternoon updates get lost when merged!
How to Avoid This Pitfall: Collaborate via a single shared cloud document using live co-authoring.
Trap 2: Granting 'Can Edit' to External Public Newsletters
Gives readers power to deface or wipe your master PDF/document!
How to Avoid This Pitfall: Publish public documents strictly with **Can View** or static `.pdf` downloads.
Trap 3: Deleting Closed Comments Without Applying Changes First
Resolving/deleting comments before addressing edits misses marks.
How to Avoid This Pitfall: Update the document first, then click `Resolve` to archive the thread cleanly.
